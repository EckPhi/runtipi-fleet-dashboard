# v0.1.0

The first collector image establishes inventory protocol version `1` and the cache-to-Homepage rendering pipeline.

## Included

- Concurrent companion polling with independent timeouts and bearer-token files.
- Strict, allowlisted inventory decoding with persistent server UUID validation.
- Durable last-success caches and offline tile retention.
- Authoritative removal following a successful inventory.
- Stopped-app visibility and browser-facing URL overrides.
- Atomic, change-only Homepage `services.yaml` generation.
- Multi-architecture GHCR image for `linux/amd64` and `linux/arm64`.
- Critical-vulnerability scanning, SBOM, and GitHub build provenance.

## Runtime contract

- Image: `ghcr.io/eckphi/runtipi-fleet-dashboard:0.1.0`
- User: UID/GID `65532:65532`
- Read-only inputs: `/config/fleet.yaml`, `/run/secrets/*`
- Writable persistence: `/state`
- Writable generated output: `/homepage/services.yaml`
- Inbound ports: none
- Docker socket: not required

Runtipi Companion inventory serving is developed separately. The collector expects `GET /v1/inventory` to conform exactly to `docs/contracts/inventory-v1.example.json`.

## Deployment status

This release is intended for its maintainer's initial deployment while Companion integration is completed. The Runtipi app-store package remains an unpublished handoff until it has been validated on Runtipi v4.10.2.
